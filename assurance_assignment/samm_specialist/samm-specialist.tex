\sectionheading{Core}
\subheading{Security Testing (Verification)}
\emph{Dedicated security test cases for known-risk areas, run regularly.}
I audited authorization, path-traversal and login-throttling tests, plus
\path{server/test/api/test_FCS_COP_1.py}. Its existing checks covered an issued
link returning HTTP 200/PDF without authentication; random, last-character-flipped,
plus-one and all-zero unissued links returning HTTP 404/no PDF; and two users'
links retrieving only their own documents and watermark secrets.
\path{.github/workflows/tests.yml} runs pytest on PRs to \texttt{main}, pushes to
\texttt{main} or \texttt{feat/**}, and manual dispatch.

\subheading{Improvement}
Before, the SHA-1(\texttt{s1}) candidate was checked only manually, and the four
negative-link cases did not check for sensitive values in responses. I automated
the exact candidate request below, which returns HTTP 404 without PDF content:
\par\texttt{GET /api/get-version/640d87e741e6aa4c669a82a4cd304787960513ab}\par
I also added assertions that all four negative responses omit both users'
watermark secrets, intended recipients and filenames.
The focused module passed all seven cases and Ruff on 30 September 2026.
Commit: \href{https://github.com/chirichexe/tatou-2026/commit/fbae18a9970c721a8809d2ff2d43ef10be03d7fc}{\texttt{fbae18a}}.

\subheading{Scorecard}
\textbf{Level 2, using the assignment rubric.} Dedicated tests for known risks
run regularly in CI; the improvement adds repeatable checks within that level.
Level 3 requires systematic coverage tracking, which is missing. The link
fixture uses in-memory SQLite and \texttt{toy-eof}; these selected cases do not
establish general link unpredictability.

\sectionheading{Further Work}
\subheading{Secure Build (Implementation) -- second practice audited}
\emph{Builds automated and reproducible; dependencies pinned.}
I audited the Dockerfile, dependency files, Compose configuration and CI.
Before the improvement, CI did not build the image and Docker ignored the local
\texttt{uv.lock}: the built image had \texttt{cryptography 50.0.2}, while the
lockfile specified \texttt{50.0.1}. A manual image build/import and
\texttt{docker compose config -{}-quiet} passed, but did not establish a pinned
build or startup of a fresh Compose stack.

\subheading{Improvement -- second real improvement}
I added a CI job that builds \texttt{./server} and runs \texttt{import rmap}
inside the image. I also added \path{server/requirements.txt}, generated with
\texttt{pip-compile}, pinning 26 registry distributions. Docker installs that
file and the project once with \texttt{-{}-no-deps}; pytest uses the same runtime
requirements. CI regenerates the file and fails on a diff; the Python base image
is pinned by digest. A clean local Docker build passed, all 26 installed versions
matched, and \texttt{pip check} and \texttt{import rmap} passed. Recorded CI run
\href{https://github.com/chirichexe/tatou-2026/actions/runs/36756093546}{\texttt{36756093546}}
passed the lock check, Docker job and Ruff; pytest reported 368 passed, 11 skipped,
2 xfailed. Commits:
\href{https://github.com/chirichexe/tatou-2026/commit/8a1073f7b43b87a0fefb77366456fb2a4518a76c}{\texttt{8a1073f}},
\href{https://github.com/chirichexe/tatou-2026/commit/f0cd7aef43f7857a6e610fd0189cc04da6c0e4e1}{\texttt{f0cd7ae}},
\href{https://github.com/chirichexe/tatou-2026/commit/f7e50c307136f364113cbdd55ce0822dc94618c5}{\texttt{f7e50c3}}.

\subheading{Scorecard}
\textbf{Level 2, using the assignment rubric, for the server image and Python
runtime dependencies.} CI automates build/import checks, installs tracked exact
versions and checks for dependency drift. System packages remain unpinned,
RMAP uses a release tag, and fresh full-stack startup was not tested. Level 3
requires a security gate: no dedicated dependency/image vulnerability scan or
confirmed required merge check is established.
